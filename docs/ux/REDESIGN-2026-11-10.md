# Desktop redesign: two rooms, 2026-11-10

Author: Sonia, with Claude. UI only (`desktop/ui/src`). No daemon, shell or detection code changed.

## What changed

- **One stylesheet, new look.** `app.css` tokens: ink-blue neutrals, one indigo accent, layered
  shadows. The page is a soft canvas (bg-200) and content sits on it as raised cards (bg-100).
  Light and dark both redone. Token names are unchanged, so every view follows.
- **Simple and Expert are two different rooms**, split with `html[data-mode]`:
  Simple is roomy, round, one centred column (920 px); Expert is tight, small radii, dense rows,
  full width (1360 px).
- **Sidebar.** Icons on every item (they were already in `nav.ts`, unused), a raised pill for the
  current page, a small eye mark, a status chip. Coverage stays in the sidebar in both modes.
  Items carry `data-view` for UI tests.
- **Simple Home.** Answer first in a hero, one big "Check my computer" button, then grouped rows
  (macOS System Settings style). The honest headlines from `plain.ts` are unchanged: it still
  never says the computer is safe.
- **"Check my computer"** refreshes the state and, where Windows virus protection can be reached,
  starts its quick scan. It is the same `protection_scan` call as "Check for viruses". Nothing new
  is sent to the daemon.
- **Plain words in Simple** (Expert wording untouched):
  - status banner groups: "Could not run", "Behind or not started", "Needs extra permission";
  - Review: "Seen {n} times" instead of "{n} observations"; the auto-handle sentence rewritten;
  - What Argus can see: the 14 ATT&CK tactics as what the attacker is doing ("Getting in",
    "Stealing passwords", "Moving to other computers" ...); "Tricks ARGUS-INSTINCT cannot spot yet";
  - Settings, Geo and the command palette: a few technical phrases replaced.
- **Fixes found on the way.** In Simple, the severity pill column was 76 px, so "Worth a look" and
  "For your info" ran into the text beside them (Findings, palette, Coverage). The status banner
  and pause notice now share the page column. The update note in the sidebar wraps instead of
  being cut off.

25 new interface strings, each added to all ten locale files (610 keys per language).

## Invariants kept

- Every number, severity and path shown is still what the daemon reported. Only layout, colour
  and Simple wording changed.
- No view, route, API call or feature was removed. Counting rules in `model.ts` are untouched.
- The product name is never translated; every locale has every key; no stale keys.
- Working-tree line endings (CRLF) preserved in every edited file.

## Proof

Run in a Linux container against a mock of the daemon API (not the real daemon):

- `vite build`: clean. `svelte-check`: 0 errors, 0 warnings.
- `bun test src/lib`: all 63 pass, including the locale, nav and pricing tests.
- Playwright walk of all 13 views x Simple/Expert x light/dark, twice:
  - browser mode with small data;
  - a faked Tauri shell with heavy data shaped like a real degraded machine (score 12,
    248 findings, 58 collectors with 13 not healthy, 15 blind checks, 36 cases, coverage
    13/131/33/2, update available).
  No page errors, no blank view, no horizontal overflow.
- Clicked through: finding detail, command palette, pause menu, banner "Show which",
  "Check my computer", answering a question, Home to Checks. Arabic (right to left) renders.

## Not done / blind spots

- **Not run inside the real Tauri window or against a real daemon.** Verified in Chromium only.
- **Translations of the 25 new strings were written by Claude** and not read by native speakers.
- Views other than Home were restyled through the shared classes, not redesigned one by one.
  Expert Overview keeps its old structure.
- First launch, phone pairing with a real phone, buying, and the assistant's real answers were
  not walked.
- `dist/` was not rebuilt in the repository.

## False alarms: what one screenshot of Sonia's machine shows (for Chris)

No detection code was changed. I could not read a live store, so nothing here is replayed;
these are candidates for the alert-quality process (ALERT-QUALITY-2026-11-08), not fixes.

The screenshot: score 12, 34 critical, 114 high, 45/58 collectors, on a cofounder's own
developer PC. A new user who sees this on a healthy computer stops trusting the product.
What stands out:

1. **Argus's own health is counted as findings about the machine.** "collector 'audio' is
   failing" (`service/coverage.py`, high; "never produced a result" is critical) and
   "detection regressed: T1543 / T1014" (`service/attackmap.py`, high) sit in the same
   critical/high totals as real observations. Invariant 6 of the alert-quality work already
   says coverage gaps are about Argus, not the machine. A failing collector and a regressed
   probe look like the same class. Question: should they leave the machine's totals and live
   only in the status banner, Checks and Coverage ("Got worse"), where they are already shown?
2. **Edition limits read as faults.** 10 of the 15 blind checks are "Administrator sensor":
   a known limit of this edition. If any of those also produce "is failing / never produced"
   findings, a non-admin install can never look healthy.
3. **"WMI event subscription" is critical unless it is the one stock Windows entry**
   (`collectors/persistence/control.py`, only "SCM Event Log" is exempt). OEM and vendor tools
   register these too. A reviewed allow-list of known vendor consumers, or high instead of
   critical without a second signal, would follow the "no single-signal critical" rule used
   for blocklists.
4. **Auto-start services under `\\AppData\\` are critical** in the same file. Many per-user
   apps install there legitimately (updaters, chat and dev tools). Same question: second signal
   before critical?
5. **"1 injected character VK_0xB3"**: 0xB3 is the media Play/Pause key. Media keys from
   headsets, keyboards' Fn layers and remote-control apps are injected by design. Worth
   checking whether media and volume virtual keys should be excluded or downgraded.

To settle any of these properly I need a read-only export of a live `/api/state` and
`/api/coverage` from a clean Windows machine, to replay before and after as the 11-08 work did.
