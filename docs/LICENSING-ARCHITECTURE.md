# Argus licensing — architecture

Status: design, 2026-11-05. Owner request: seamless, secure, lightweight, efficient.

## 1. What "secure" means here

| Protected (cryptographically or server-side) | Not protectable on the client |
|---|---|
| Payment → entitlement: only a verified Stripe event creates a licence | A user who patches the Argus binary can skip any local check |
| Licence certificates can't be forged or edited (Ed25519) | |
| A copied certificate doesn't work on another machine (device binding) | |
| A leaked key can't renew someone else's activation (device-key proof) | |
| Keys, emails and machine IDs can't be read from a database leak (hashes only) | |
| Brute force and enumeration (≥100-bit keys, rate limits, uniform answers) | |
| **Server-delivered premium value is fully gated** (§7) | |

So there are two tiers:
- **Gated by the server (secure).** Anything the server delivers (content packs, updates, hosted analysis) is served only against a valid, unrevoked licence, checked on every request. A patched client gets nothing.
- **Gated locally (casual-sharing protection).** Purely local features check a signed lease offline. Bypassing them needs a modified binary, which signed releases make visible.

**Never gated:** detection, collectors, alerts, evidence, on-demand checks (`tests/test_licence_never_gates_core.py`).

## 3. Identifiers and keys

- **Licence key** (what a person types or receives): `ARGUS-SRV-XXXXX-XXXXX-XXXXX-XXXXX` or `ARGUS-DSK-…`.
  - Crockford base32: 20 symbols, 100 random bits, plus a mod-37 check symbol.
  - Case-insensitive, and accepted with or without spaces and dashes.
  - The server stores `key_hash = HMAC-SHA256(KEY_PEPPER, key)` plus the last 4 characters. A pepper (a Worker secret) means a database leak can't even be brute-forced offline.
- **Licence id** (`lic_…`, random) is public inside certificates; the key never appears there.
- **Device key**: generated by the app at first activation (Ed25519). It's stored locally: Windows DPAPI-protected (desktop), or a 0600 file under the `argus` user (server edition). The server keeps only the public key.
- **Fingerprint**: `HMAC-SHA256("argus-fp-v1:" + lic_id, machine_id)`.
  - machine_id is `/etc/machine-id` on Linux, or MachineGuid on Windows (read from the desktop edition).
  - Salted per licence, so it can't be correlated across licences.
  - Raw identifiers never leave the machine.
- **Signing keys**: Ed25519, with a `kid`. The private key is a Worker secret (`LICENCE_SIGNING_KEY`), separate for test and live. The app embeds the current and next public key, so rotation is a normal release.

## 4. The licence certificate (lease)

The format is a JWS in compact form with `alg: EdDSA`: standard, small (~350 bytes), and verifiable with any Ed25519 library.

```json
{ "iss": "pay.archymedes.xyz", "aud": "argus", "kid": "2026-11-a",
  "sub": "lic_…", "plan": "server", "seats": 1,
  "act": "act_…", "dev": "<fingerprint hash>", "dpk": "<device public key>",
  "iat": 1762300000, "exp": 1764892000,          // lease: 30 days, never past lic_exp
  "lic_exp": 1793836000, "renew_after": 1764287000 }
```

The client accepts it offline only if every one of these holds:
- the signature is valid;
- the `kid` is known;
- `aud` is `argus`;
- `dev` equals this machine's fingerprint;
- `dpk` equals this device's public key;
- `iat` − 10 min ≤ now < `exp`;
- now ≥ the last verified time − 10 min (rollback guard: last-seen is kept in the lease state, MAC'd with the device key);
- `plan` matches the feature.

Verification is a single Ed25519 check (tens of microseconds), with no network.

## 5. Flows

### 5a. Buy from inside Argus (seamless, no typing; device authorization flow like RFC 8628)
1. The person clicks **Upgrade** in Argus. The app generates a device key and calls `POST /licence/claim {dpk, dev}`.
2. It gets back `{claim_id, user_code: "K7QF-M2XD", verify_url}`, valid for 15 minutes; only its hash is stored.
3. The app opens the browser at `/buy/argus-server?claim=claim_id`, and the Checkout Session carries `metadata[claim]`.
4. The Stripe webhook arrives, creates the licence, binds it to the claim and activates that device.
5. The app polls `POST /licence/claim/poll {claim_id, sig}` every 5 s while its window is open; the request is signed by the device key, so only the device that started the claim can collect it. It receives the certificate.
6. Argus is activated. The key is still emailed, for other machines and for recovery.

### 5b. Bought on the website
- The thank-you page shows the key once, with **Copy** and **Open in Argus** (`argus://activate?key=…`, registered by the desktop installer).
- The same key is in the email.
- On a headless server, run `argus licence activate` and paste the key. Alternatively, `argus licence login` shows a short code and a URL (the same claim flow, approved in the browser after signing in with the purchase email).

### 5c. Activate with a key
1. The client sends `POST /licence/activate {key, dev, dpk, label}`.
2. The server checks: the key hash, the status (active), seats free, and the release limit.
3. It creates the activation and returns the certificate. The same device asking again gets the same activation and a fresh certificate.
4. A different device with the seat taken gets 409 `seat_taken`, plus the manage URL.

### 5d. Renewal (automatic, quiet)
1. When Argus is running and now > `renew_after` (lease − 7 days), the client sends one request: `POST /licence/renew {act, nonce, ts, sig}`.
2. It's signed with the device key over (act, nonce, ts), and ts must be within 5 min.
3. The server checks the licence is still active (subscription paid, not refunded) and returns a new certificate.
4. If it fails, it retries with backoff (6 h, then daily). Argus keeps working until `exp`; after that, only local premium features ask for a check.
5. It can be turned off (`licence.auto_renew = false`). Renewal then happens through `argus licence refresh`.

### 5e. Release / move / recover
- **From the machine:** `argus licence deactivate`, or **Deactivate** in the app. It's a device-signed `POST /licence/release`, and the seat is freed at once.
- **From the web:**
  1. Request the manage page at `/manage`. The person enters the purchase email; only a hash of that email is compared against `email_hash` (an HMAC with the pepper, saved when the licence was created).
  2. If it matches, a single-use magic link is emailed: 15 minutes, hashed in D1.
  3. The link opens a short session (30 min, `HttpOnly; Secure; SameSite=Strict`, CSRF token on POSTs).
  4. On the page: see activations, release a machine, resend the key, open the Stripe billing portal.
- **Lost key:** `/recover` with an email always answers the same way. If it matches, the keys are emailed. Neither flow stores plaintext emails.
- **Abuse limit:** 3 releases per licence per 30 days. Beyond that, the person contacts support (with an audit log).

### 5f. Payment events → licence state
| Event | Effect |
|---|---|
| `checkout.session.completed` | Create the licence (idempotent by session) and email the key. |
| `invoice.paid` | Extend `lic_exp` to the period end. |
| `customer.subscription.deleted` | Set `revoked_at`; renewals fail and server content stops at once. |
| `charge.refunded` | Find the licence (by subscription/invoice) and revoke it. |

Events whose `metadata.app` isn't `argus` are dropped first. Event ids are stored for idempotency, and every Stripe call pins `Stripe-Version`.

## 6. Data model (D1)

```
licences     (id PK, key_hash UNIQUE, key_last4, plan, seats, status, lic_exp, email_hash, customer, subscription,
              session_id UNIQUE, livemode, created_at, updated_at, revoked_at)
activations  (id PK, licence_id, dev_hash, device_pubkey, label, created_at, last_renewed_at, released_at)
claims       (id_hash PK, dev_hash, device_pubkey, licence_id NULL, expires_at)
magic_links  (token_hash PK, licence_ids, expires_at, used_at)
releases     (licence_id, at)          -- rate limit for moves
events       (stripe_event_id PK, type, at)
audit        (at, licence_id, action, actor)   -- no keys, emails or IPs
```

Every lookup is a single-row read by a hashed primary or unique key.

## 7. Making the premium value secure (owner decision)

A local check can always be patched, so the only fully secure gate is **value the server delivers**. Argus can move part of its premium value there without sending host data out:
- **Signed content packs.** For example: the premium review report's templates and scoring rules, curated detection packs, intel updates. Served from `/content/:pack` only with a valid certificate and a device-signed request, and signed by the server so the client can trust them.
- **Optional hosted analysis.** Only if the owner wants it. It sends summarised findings, never raw host data, and needs explicit consent.

Then even a patched client gets no new packs or updates, while core detection stays free and local.

## 8. Efficiency
- **Per machine:** one activation, then one renewal about every 23 days; claim polling happens only during a purchase.
- **Worker cost:** under 5 ms CPU per request, single-row D1 reads; comfortably inside Cloudflare's free tier at expected volume.
- **Client:** one small module, no SDK. Ed25519 verification comes from `cryptography` (already a common wheel; it has to be bundled for the Windows embeddable Python). Certificates are about 350 bytes.

## 9. Secrets and operations

| Secret | Where |
|---|---|
| `LICENCE_SIGNING_KEY` (Ed25519, kid) | Worker secret, separate for test and live |
| `KEY_PEPPER` | Worker secret (HMAC for key and email hashes) |
| `STRIPE_SECRET_KEY` (Argus runtime restricted key), `STRIPE_WEBHOOK_SECRET` | Worker secrets |
| Email API key | Worker secret |

- **Rotation:** release a client that knows the new kid, switch the signing kid, keep the old kid trusted until the old leases expire (30 days), then remove it.
- **Releases:** the embedded public keys are only as trustworthy as the release, so Argus builds stay signed.

## 10. Tests that must exist

The client must reject:
- a tampered certificate;
- an unknown kid;
- a wrong `aud`;
- the wrong fingerprint;
- the wrong device key;
- an expired lease;
- a clock rolled back past the last-seen time;
- a revoked licence at renewal;
- a replayed renew request (old ts or reused nonce).

The server must:
- give a seat-taken 409 with the manage URL;
- enforce the release limit;
- answer uniformly on `/recover` and `/manage`;
- use magic links once only, and expire them;
- treat webhooks idempotently and drop other apps' events.

Core detection is never gated.
